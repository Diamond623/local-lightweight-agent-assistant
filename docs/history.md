## 9.26：Agent 分段读取与精确替换长文件

项目里的 Agent 现在可以按起始行分段读取较长的代码文件，并用 `propose_patch` 对唯一原文做精确替换。补丁会先核对已读取文件的版本和原文唯一性，再检查 Python / JSON / TOML 的完整修改后内容；冲突、重复原文或语法错误都不会生成建议。成功后仍只保存待审差异，原文件由用户在项目面板确认应用；不执行代码和测试。单个项目文件仍限定在 100 KB 内。

## 9.26：Agent 在项目里搜索代码并校验修改建议

在项目对话开启 Agent 后，它可以用文字关键字在当前账号的项目工作区内搜索文件与行号、读取匹配文件、检查拟修改的 Python / JSON / TOML 完整内容，再创建供用户查看差异的修改建议。搜索限于非隐藏的普通文本或代码文件，最多扫描 200 个文件、返回 15 处匹配；不跟随符号链接或硬链接。语法检查只解析文本，不执行用户代码、测试或任意命令；其他文件格式会明确标为未检查。无效 Python / JSON / TOML 语法不会进入 Agent 的待审修改。Agent 最多执行 6 次项目工具步骤以容纳检查失败后的修正，文件仍需用户在项目面板审核并应用。

## 9.26：在聊天中读取这台 Mac 的当前信息

要让客户端使用统一账号，将 `account-service.example.json` 复制为 `account-service.json`，填写共同的服务地址并重启客户端；也支持环境变量 `AURORA_ACCOUNT_URL`。当前 example 指向本机试用服务。外网地址必须使用 HTTPS；其他电脑上的 127.0.0.1 指向它自己，不是你的 Mac。服务始终仅监听本机，需要另行配置 HTTPS 反向代理和稳定地址才能供别人连接。反向代理需保留 Host；启动服务时用 `--public-origin https://accounts.example.com` 明确域名，此模式禁止空库抢注管理员。客户端拒绝重定向，服务停机时拒绝认证，不会回退为离线管理员。

客户端只发送注册、登录、改密和账号管理字段。聊天、文档、图片、记忆不上传到账号服务。统一账号模式的数据保存在本机 `Aurora Memory/services/<服务标识>/<账号编号>`，不会与原本机账号或另一服务器同编号账号混合，也不会自动同步旧聊天。模型继续在使用者电脑运行。停用会撤销全部会话，但无法删除用户电脑上已有的本地数据。

统一账号模式下，任务仅在 Aurora 打开、用户已登录且账号服务可连接时执行；暂不支持退出 Aurora 后的后台任务。普通本机账号原有后台机制保留。此版本没有自动采集训练数据、邮件找回密码、付费系统、自动 HTTPS 或生产部署。分发时必须排除 data、models、account-service.json、后台任务数据及任何凭据。更新包仅附地址示例，不包含账号数据库或会话。

“＋ 文档”支持 PDF、DOCX、TXT、Markdown、CSV 和代码文本，单文件最多 20MB。PDF 工具使用 macOS PDFKit，已附编译后的 PDFRead；如需重新编译，执行 Prepare-Documents.command。

PDF 最多读取前 200 页文字；文字较少的页面最多取 2 页转换成图，供多模态模型查看。Word 提取正文与表格文字，不解析内嵌图片和公式对象。长文最多保留前 20 万字符，每次按问题选择至多约 2000 字片段；“概括全文”仅抽取开头、中间、末尾，不能等同于精读整篇。

当前附件在窗口里保留，可继续问不同问题；移除附件、切换对话或关闭窗口后，需要重新上传。数据库只保存本轮实际引用的片段与回答，不保存原始文档。图片上传功能继续使用，当前主力模型可同时处理文字和图片。

在 Apple Silicon Mac 上使用 llama.cpp 的独立桌面聊天窗口。Python 标准库负责本地接口、SQLite 记忆和搜索，Swift / WebKit 显示窗口；不需要安装 Python 第三方包。

在终端执行（整个 Aurora 文件夹须保留在一起）：


首次启动会用 Xcode Command Line Tools 编译桌面窗口。若放入其他目录，可为 Start.command 创建 Finder 替身放到桌面。不要只复制脚本，其他文件也要保留。

目前文字模型使用已有的 Ollama GGUF 文件，路径在 app.py 的 MODEL 常量中。不要删除这份权重。文字模型接口使用 8080，看图模型使用 8081。已有服务可以复用，不接管、不停止已有服务；新服务由本窗口启动，退出窗口时停止。

## 使用

- 点击“启动所选模型”，等待就绪。文字模型复用本地 Qwen3 8B。
- 选择“看图 · Qwen3-VL 4B”并启动，第一次从 Qwen 官方 Hugging Face 仓库下载 Q4_K_M 权重和配套视觉编码器。失败信息在“状态详情”，需联网可达 Hugging Face。不会绕过 TLS 验证。
- 图片缩至最长边 1600 像素，本地保存至聊天记录。当前图片可连续追问，每轮继续传给本地视觉模型；移除附件、切换对话或关闭窗口后，需重新上传。
- 允许联网：身份、个人记忆、写作、解释、代码和普通附件分析在本地完成；需要外部信息的任务才搜索。明确要求联网、搜索或核实时优先执行。先用本地模型从当前问题逐字提取地点，没有固定城市表。明确的新地点始终优先；“明天呢”“会下雨吗”“那里有什么景点”等指代，可从上一轮已验证的查询元数据补全地点。“简短一点”“为什么”“举个例子”等承接上一轮回答，不重复搜索。优先百度、360 搜索，失败时继续尝试 DuckDuckGo HTML、Bing RSS；读取实际网页正文、检查实际标题属于本轮地点，再向本地模型提供至多约 3000 字摘录并显示来源。联网回答不注入旧网页事实和旧对话，避免旧城市数据混入；仅保留明确的称呼、语言和回答风格偏好。记录仍完整保存供本地聊天使用。不能读取正文或地点不符时明确报错。公开搜索和网页可能超时、要求验证或过时，成功读取也不保证信息实时。
- 可以直接说“记住：我叫……”保存长期信息；明确指令由程序保存，避免只口头承诺。也可在“记忆”中添加、编辑和删除。SQLite FTS5 检索全部已存记忆和历史文字：英文词、中文双字词匹配，不再只取最近 30 条。每次最多约 1800 字相关资料，同时参考少量最近偏好，控制上下文占用。
- 聊天成功后自动保存，关闭重开可回看。通常累计至少 8 轮后排队，闲置 30 秒再整理较早的 6 轮，留下最近 2 轮原文；后续分段整理，避免刚回复就抢占下一条聊天。摘要由当前本地模型生成，可能有误，不等于用户确认的事实。
- “记忆 → 整理当前对话摘要”可处理旧对话，一次最多 3 段。至少 3 轮时才有可整理内容，始终保留最近 2 轮原文。整理期间模型会短暂被占用；失败不影响原文。
- 摘要列表显示原对话和消息范围，可查看原文或删除摘要。删除摘要不删除原文，之后可能再次生成；彻底移除一段对话及其衍生索引，请删除原对话。删除手动记忆不删除历史中的副本。
- 回答下方可展开“本次参考了 N 条记忆”，查看本轮使用的资料。原始聊天完整保存不代表每次都准确检索；同义改写可能漏检。
- 回复长度有限，达到上限会标注，可继续追问。

## 数据与隐私

数据在同目录 `data/memory.sqlite3`（含聊天、图片和长期记忆），日志在 `data/text.log`、`data/vision.log`。不要分享 data 文件夹。此版本没有加密数据库，受本机账户和磁盘保护。联网发送本轮搜索词；省略问句可能补充上一条用户问题的话题，不向搜索服务发送图片、整段历史或长期记忆。下载模型会连接 Hugging Face。

本地界面仅绑定 127.0.0.1，接口使用每次启动随机令牌。没有任意命令执行、鼠标键盘接管或网页自动点击功能。

## 检查与限制

如 data 是指向桌面 Aurora Memory 的软链接，程序继续使用该目录；目标不存在时启动会尝试创建它。首次升级已有数据库时，生成 memory-before-retrieval-v1.sqlite3 备份后建立检索索引。测试用临时数据库，不触碰用户数据。

编译和业务逻辑可单独检查。完整看图依赖模型成功下载与本机 GPU。搜索依赖 Bing RSS 可用性，可能被网络或服务限制。生成内容是纯文本显示，避免将模型输出当成网页代码执行。

## 地点约束和网页读取

窗口顶部显示运行版本。升级后完全退出旧窗口，再从桌面重新打开 Aurora；应看到 Aurora-8。

问“珠海今天天气如何”后再问“广州呢”，会重新查询广州，并读取标题明确包含广州的网页。搜索摘要写珠海、实际打开标题却是成都的页面会被丢弃；当前天气不使用历史天气页。缺少地点时先询问，解析失败或没有匹配网页时明确失败，不沿用其他地点的结果。不再使用 Open-Meteo 地理编码或城市别名字典替代用户地点。

支持天气之外的地点问题，例如“广州有哪些旅游景点”。支持粘贴公开网页链接读取正文；不访问本地或内网链接。网页会去掉脚本和部分导航，最多读取约 2MB，再截取相关段落；这不等于阅读全文。本地 DNS 不可用或返回 TUN 虚拟地址时，先用 AliDNS、再用 Cloudflare 公开 DNS 校验域名对应公网地址；本地、内网和字面量虚拟地址仍拒绝访问。无法校验时不读取。

解析仍由本地模型完成，可能漏识别或误判。多地点问题要求来源标题覆盖所有提取到的地点，否则明确失败。过短或歧义地名建议补充省份/国家。

## 桌面联网可靠性更新 Aurora-web-7

国内搜索入口优先；某入口没有结果、要求验证或页面读取失败时，自动换用其他入口。读取到覆盖当前地点的网页即可回答，不再为凑足两个来源继续等待。每轮仍重新搜索，DNS 的短时缓存不缓存查询结果或天气数据。

“状态详情”的联网记录显示本轮查询词、各搜索入口的匹配数量、读取成功的网页及失败原因；不再把超时、证书、DNS 和地点不符全部隐藏。正常回答仍只使用实际读取的正文，当前天气优先选择今天/实时部分，降低周边推荐、新闻列表等内容的权重。

## 9.16 项目工作区与任务执行台

侧栏「项目工作区」可创建项目，保存目标和进度，再关联当前对话或新建项目对话。关联是按对话保存的；新建普通对话不会自动继承项目。每个账号使用自己的项目数据库与 `workspaces/<项目编号>` 文件夹，面板显示实际目录。把支持的 UTF-8 文本或代码放入该目录，或通过文件编辑区创建文件；不访问任意外部目录。

项目对话开启 Agent 后可查看项目信息、列目录、读取文件、提出完整文件修改。单轮工具上限仍为 4 步；现有文件必须先读取，Agent 只修改完整读取且不超过 2000 字的文件。文件编辑区支持每文件最多 100 KB。模型可能无法正确规划或输出较长 JSON，执行台如实记录失败，不把回答当成任务已全部完成。

所有修改先保存为待审建议，在「待审修改与撤销」展开差异，点击应用才会写入。支持撤销、忽略，应用与撤销前检查文件内容是否仍匹配；有冲突时停止，不覆盖外部修改。符号链接、硬链接、隐藏路径和越界路径不可访问。此版本不执行项目代码或 shell 命令。

执行台持久保存原问题、步骤、结果与状态；可以打开原对话、停止当前轮次、载入原问题重试（仍需点击发送）。不是暂停后从原步骤自动续跑。程序重启后遗留运行状态标记为中断。项目进度由用户编辑保存，不让模型自动覆盖；关联项目的名称、目标、进度会作为后续对话参考。


## 9.16.1 项目稳定性修复

- 当前窗口按项目保留尚未保存的目标、进度和文件草稿，刷新或切换项目不会覆盖草稿；关闭应用后仍需依靠已保存的内容。
- 文件读取请求校验项目、路径和编辑版本，过期响应不能覆盖新项目或正在输入的文本。放弃文件草稿后重读需要明确确认。
- 手动编辑必须基于已读取的文件版本；从读取到生成建议、从建议到应用、从应用到撤销均检查冲突。新文件不需要预先读取。
- 待审修改全部应用或忽略后，任务显示“修改已处理 · 请核对产出”，不再一直等待审核，也不等同于确认任务成功。
- 写入失败且原文件未改变时，恢复待审状态，允许重试；磁盘内容存在不确定变化时保留待核对状态。
- 新建项目对话在同一数据库事务中创建并关联，不会误用旧对话。Agent 重复提出同一修改时跳过重复步骤。
